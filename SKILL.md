# Work-record templates

Create the record needed for the current work and use the authorized delivery route. Do not merely describe how to write it. These templates present evidence; they do not grant authority, create approval stages, or mandate other skills.

## Select and ground

Identify the actual audience and transition. Read only the applicable template:

- Dispatch implementation or investigation: [executor assignment](templates/executor-assignment.md).
- Assign supervision or candidate acceptance: [reviewer assignment](templates/reviewer-assignment.md).
- Report work actually done: [execution result](templates/execution-result.md).
- Decide from inspected work: [review](templates/review.md).

Recover the original goal, effective scope, current candidate and material constraints from their authoritative sources. Supply the audience with the substance it needs, not only a locator. Keep one authority for shared goal/scope while projecting it for each audience. Ask only for a consequential missing fact; do not invent actor, revision, result or permission.

The host's existing required fields and meanings take precedence. Preserve parser names, iteration versus repair labels, exact completion requests, executor evidence and supported unknown/null values when applicable. Do not reset a session, transform old records or resend completed work to fit a template.

## Produce and deliver

Populate the selected file using actual facts. Delete irrelevant optional prompts instead of filling them with boilerplate. Keep material uncertainty explicit. For an assignment, describe permitted effects and the observable result required; do not prefill eventual acceptance. For a result, include failures and checks not performed. For a review, distinguish inspected evidence from reports and bind its decision to the actual candidate.

If authorized to save or send the record, use the identified owning work item or existing conversation. Preserve the intended audience and redact unnecessary private coordination details. Read back durable content and its link before claiming it is saved. If only drafting is authorized, return the draft and state it has not been delivered. Do not create an Issue, publish a file, or expose private information solely because a template has a destination slot.

For a real assignment, confirm it reached the intended executor through the supported route. Match the returned result to that assignment. The responsible reviewer inspects actual artifacts and decides the next action using the active review method. A second model's participation is not inherently independent verification.

## Verify usefulness

A completed record lets the intended reader determine what outcome was requested, which effects were allowed, what actually happened, what supports the decision and what remains. Use a fresh reader when needed to verify recovery from the saved record; do not leak an intended answer into that check.

Formatting or filled fields alone are not acceptance. Keep publication, loading, actual use and parent completion separate. Each template can be used alone, updated independently or replaced by equivalent prose without changing the host's obligations. No sibling package is required.
